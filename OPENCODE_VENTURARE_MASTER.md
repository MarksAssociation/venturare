# 1. MODO DE OPERAÇÃO

Você está trabalhando no site institucional da **Venturare**, uma
consultoria boutique premium de estratégia, tecnologia, inteligência,
execução e transformação.

Seu papel não é apenas escrever código.

Você deve atuar simultaneamente como:

1.  Arquiteto de software;
2.  Desenvolvedor front-end;
3.  Diretor de arte digital;
4.  Estrategista de marca;
5.  Redator institucional;
6.  Especialista em UX/UI;
7.  Especialista em acessibilidade, SEO e performance;
8.  Revisor crítico de consistência;
9.  Responsável por preservar a identidade da Venturare.

## Regra principal

**Não implemente mudanças apenas porque elas parecem tecnicamente
possíveis.**

Toda mudança deve preservar:

-   clareza;
-   sofisticação;
-   coerência narrativa;
-   consistência visual;
-   simplicidade;
-   conversão;
-   performance;
-   identidade da marca.

Quando houver conflito entre adicionar conteúdo e manter clareza,
**prefira clareza**.

Quando houver conflito entre efeito visual e sofisticação, **prefira
sofisticação**.

Quando houver conflito entre uma solução genérica e uma solução coerente
com a Venturare, **prefira a solução coerente com a Venturare**.

# 2. OBJETIVO DO PROJETO

Construir um site institucional premium, editorial, contemporâneo e
estratégico para a Venturare.

O site deve comunicar que a Venturare:

-   compreende o negócio antes de propor tecnologia;
-   transforma complexidade em clareza;
-   conecta estratégia, tecnologia e execução;
-   estrutura capacidade de execução;
-   trabalha com direção, método e responsabilidade;
-   transforma visão em resultados concretos e sustentáveis.

O site não deve parecer:

-   uma software house genérica;
-   uma agência de marketing;
-   uma empresa de outsourcing tradicional;
-   uma startup SaaS;
-   um catálogo de serviços;
-   uma página excessivamente textual;
-   um template de consultoria corporativa;
-   um site com estética tecnológica genérica.

# 3. IDENTIDADE DA MARCA

## 3.1 Nome

**Venturare**

## 3.2 Slogan oficial

**TRANSFORMANDO VISÃO EM RESULTADOS**

Este é o slogan oficial da marca.

Não substituir por:

-   Estratégia que transforma;
-   Onde estratégia encontra inteligência;
-   Tecnologia com propósito;
-   Transformando negócios;
-   Qualquer outro slogan alternativo.

Outras frases podem ser utilizadas como títulos, posicionamento ou
manifestos, mas nunca devem substituir o slogan oficial quando o
contexto exigir a assinatura da marca.

## 3.3 Posicionamento

A Venturare conecta estratégia, tecnologia e execução para transformar
desafios complexos em movimentos claros e resultados sustentáveis.

## 3.4 Frases centrais da marca

Utilizar com critério, sem repetir excessivamente:

-   **Não começamos pela tecnologia. Começamos pela compreensão.**
-   **Estratégia antes da tecnologia.**
-   **Negócio antes da execução.**
-   **Tecnologia sem direção acelera o caminho errado.**

-   **Não vendemos pessoas. Construímos capacidade de execução.**
-   **A composição do time muda conforme o desafio. A direção não.**
-   **Antes de decidir, compreenda.**

-   **O maior risco não é tomar a decisão errada. É tomar a decisão
    certa sobre uma realidade mal compreendida.**
-   **O futuro não começa na execução. Começa na compreensão.**

# 5. SISTEMA VISUAL

## 5.1 Paleta principal

``` text
Preto base:       #080A0B
Grafite:          #111518
Azul profundo:    #0B1B26
Azul secundário:  #123142
Verde Venturare:  #2EB837
Branco:           #F5F7F6
Cinza secundário: #9BA5A8
Borda:            #263237
```

## 5.2 Uso recomendado das cores

Proporção aproximada:

-   70% preto, grafite e fundos escuros;
-   20% branco e cinzas;
-   8% verde Venturare;
-   2% elementos de destaque.

O verde deve ser usado para:

-   CTAs;
-   pequenos labels;
-   números;
-   palavras enfatizadas;
-   linhas de trajetória;
-   estados ativos;
-   detalhes de interação.

Não utilizar verde em grandes áreas sem necessidade.

## 5.3 Cobre ou metálico

A cor cobre `#B8895A` pode ser utilizada apenas como experimento
pontual.

Não é cor oficial da marca.

Não utilizar no sistema principal sem aprovação explícita.

## 5.4 Tipografia

Preferência:

-   **Manrope** para títulos e elementos de interface;
-   **Inter** para textos corridos e interface;
-   **Cormorant Garamond** ou **DM Serif Display** apenas quando houver
    necessidade editorial específica.

A tipografia deve transmitir:

-   precisão;
-   modernidade;
-   maturidade;
-   elegância.

Evitar fontes excessivamente futuristas, arredondadas ou decorativas.

## 5.5 Escala tipográfica

A escala deve ser responsiva.

Referência para desktop:

-   Hero: aproximadamente 64--88px;
-   H1 interno: aproximadamente 56--76px;
-   H2: aproximadamente 36--52px;
-   H3: aproximadamente 22--30px;
-   corpo: 16--18px;
-   texto auxiliar: 13--15px;
-   labels: 10--12px, com espaçamento entre letras.

Não reduzir títulos a ponto de perder presença.

Não aumentar títulos a ponto de prejudicar leitura.

## 5.6 Layout

-   Grid principal de 12 colunas no desktop;
-   largura máxima aproximada: 1200--1280px;
-   margens amplas;
-   seções com espaçamento generoso;
-   alinhamento consistente;
-   conteúdo centralizado dentro do grid;
-   mobile com uma coluna principal;
-   tablet com adaptação intermediária.

# 6. PRINCÍPIO EDITORIAL

Toda seção deve seguir, sempre que possível:

``` text
TAGLINE FORTE
↓
UMA FRASE DE CONTEXTO
↓
PROVA, EXPLICAÇÃO OU ESTRUTURA
↓
CTA, QUANDO NECESSÁRIO
```

## 6.1 Regra de economia textual

Se a tagline já comunica a ideia, não repetir a mesma mensagem em um
parágrafo.

Exemplo ruim:

> Tecnologia sem direção acelera o caminho errado.
>
> Isso significa que a tecnologia, quando não possui direção
> estratégica, pode fazer com que as empresas avancem em caminhos
> inadequados.

Exemplo correto:

> **Tecnologia sem direção acelera o caminho errado.**
>
> Antes de construir, definimos o que precisa mudar e por quê.

## 6.2 Regra de densidade

Cada seção deve ter uma função clara.

Não criar seções apenas para preencher espaço.

Evitar:

-   três parágrafos quando uma frase resolve;
-   listas longas;
-   excesso de cards;
-   explicações repetidas;
-   títulos genéricos;
-   blocos com a mesma estrutura visual em sequência excessiva.

## 6.3 Regra de hierarquia

O usuário deve entender cada seção nesta ordem:

1.  O que está sendo dito;
2.  Por que isso importa;
3.  Como a Venturare atua;
4.  Qual é o próximo passo.

globalmente por `BaseLayout` (`PageLayout` e `SolutionLayout`
delegam para `BaseLayout`; nenhuma página renderiza Header
diretamente). O `header` usa `fixed top-0 left-0 right-0 z-50` e o
componente inclui `#header-spacer` (`h-16 lg:h-20`) que reserva o
espaço correto no fluxo. Nenhum ancestral aplica `transform`,
`overflow` restritivo ou margem negativa sobre o Header.

Se o Header aparecer no meio da página em screenshot full-page,
trata-se de **artefato de captura**, não de bug do site:

-   o CSS global define `scroll-behavior: smooth`, de modo que
    `window.scrollTo(0, 0)` programático anima em vez de saltar;
    capturar durante a animação pinta o header fixo fora do topo;
-   correção obrigatória no script de captura
    (`screenshots/take-screenshots.cjs`): usar
    `behavior: 'instant'`, aguardar assentamento (~600ms) antes de
    capturar e usar `--hide-scrollbars`.

O Header deve: existir uma única vez; começar no topo; nunca
sobrepor textos ou seções; funcionar no início, meio e fim do
scroll, em desktop, tablet e mobile. Validar no navegador real e em
screenshot de página inteira.

## 36.3 Elementos estranhos --- veredito documentado

A pequena barra flutuante escura com ícones visível nas capturas
**não faz parte do site**. É a **Astro Dev Toolbar**, injetada
apenas pelo servidor de desenvolvimento (`astro dev`, shadow root
`ASTRO-DEV-TOOLBAR`). Verificação: DOM ao vivo contém um único
elemento `fixed` (`#site-header`); a barra aparece até sobre
`about:blank`-equivalente servido e some no build publicado. Nada a
remover do código. O script de captura deve ocultá-la via CSS
(`astro-dev-toolbar { display: none !important; }`). Nenhum
controle de edição, debug ou ferramenta visual pode aparecer no
site publicado.

## 36.4 Trajetória --- regra de visibilidade

A trajetória (conceito proprietário, §4.2) deve ser perceptível,
mas sofisticada: linha ou eixo contínuo, pontos de conexão claros,
números consistentes, contraste suficiente, aparência editorial,
animação discreta apenas em hover, suporte responsivo. Proibido:
efeito neon, gráfico de dashboard, animação contínua, conflito com
o Header. Em `/como-pensamos`, os seis movimentos
(Compreensão → Visão → Estratégia → Tecnologia → Execução →
Resultados) devem formar uma linha visual contínua; a linha
vertical dos seis passos e o eixo da seção prática devem usar
contraste suficiente (verde/borda com opacidade legível, nunca
quase invisível).

## 36.5 Tipografia, contraste, espaçamento --- regras de correção

Manter: Headings Manrope; Body Inter; serif/itálico somente como
detalhe editorial; paleta oficial; alto contraste nos títulos;
textos secundários legíveis. Hierarquia obrigatória:
Eyebrow → Headline → Contexto → Explicação → CTA. Não aumentar
tudo indiscriminadamente. Corrigir textos pequenos demais, labels
pouco legíveis, números com contraste insuficiente, headlines sem
força e hierarquia inconsistente. O site não deve parecer uma
interface SaaS com textos minúsculos.

Espaçamento: corrigir `min-height` excessivo, padding repetitivo,
margens artificiais e distância entre título/conteúdo e entre
seções. Preservar espaço negativo apenas quando tiver função
narrativa. Não adicionar conteúdo para preencher espaço.

## 36.6 Validação obrigatória da correção

Antes de concluir: `astro check` (0 erros); `npm run build` (todas
as rotas); Header e Footer corretos em todas as páginas; desktop,
tablet e mobile; screenshot full-page sem artefatos; scroll no
início, meio e fim; sem overflow horizontal; contraste;
imagens/assets; ausência de toolbars ou placeholders; logo e
slogan oficiais; trajetória perceptível; SEO e metadata. Entregar:
arquivos criados/alterados/removidos, problemas, correções,
resultado dos testes, rotas validadas, pendências reais e
screenshots atualizados. Não iniciar outra fase após a correção.
Aguardar nova autorização.

# 37. SISTEMA DE TEMAS --- CLARO E ESCURO

O site Venturare suporta dois temas: **escuro** (padrão) e **claro**.
Todas as novas páginas e componentes devem usar tokens semânticos para
cores, nunca cores fixas hardcoded.

## 37.1 Arquitetura

- `data-theme="dark"` / `data-theme="light"` no elemento `<html>`.
- CSS custom properties em `global.css` (`:root` = dark, `[data-theme="light"]` = light).
- Tailwind config mapeia variáveis CSS para classes utilitárias semânticas.
- Persistência via `localStorage` chave `venturare-theme`.
- Flash prevention: `<script is:inline>` no `<head>` do `BaseLayout.astro`.

## 37.2 Tokens semânticos (usar estes, NUNCA cores fixas)

| Uso | Classe Tailwind | Variável CSS |
|---|---|---|
| Fundo da página | `bg-background` | `--color-background` |
| Texto principal | `text-foreground` | `--color-foreground` |
| Texto secundário | `text-muted` | `--color-foreground-muted` |
| Superfície/cards | `bg-surface` | `--color-surface` |
| Superfície elevada | `bg-surface-elevated` | `--color-surface-elevated` |
| Acento/verde | `text-accent`, `bg-accent` | `--color-accent` |
| Bordas | `border-border` | `--color-border` |
| Navy (destaque) | `bg-navy` | `--color-navy` |
| Fundo do input | `bg-input-bg` | `--color-input-bg` |
| Placeholder | `text-input-placeholder` | `--color-input-placeholder` |
| Foco | `ring-accent` | `--color-focus-ring` |
| Texto sobre verde | `text-green-fg` | `--color-green-fg` |
| Erro | `text-error` | `--color-error` |

## 37.3 Regras para novas páginas

1. **Sempre** usar classes semânticas (`bg-background`, `text-foreground`, etc.).
2. **Nunca** usar `bg-venturare-black`, `text-venturare-white` etc. em markup.
3. Cores `venturare-*` (brand) são estáticas e só para uso em contexts
   específicos (tag categories, skip link, gradientes de imagem).
4. Gradientes sobre imagens devem usar `from-background`, `via-surface`
   etc. para adaptar com o tema.
5. SVGs com `filter: brightness(0) invert(1)` devem ter classe
   `logo-wordmap` e regras CSS dedicadas para light/dark.
6. Formulários: usar classes `.input`, `.label` do `global.css`.

accent `#2EB837`, border `#263237`.

**Light:** bg `#F7F8F7`, surface `#FFFFFF`, fg `#0B1B26`, muted `#52616B`,
accent `#168A46`, border `#DCE3E1`.
